Planteamiento del Problema

En la administración de sistemas corporativos, la seguridad suele tratarse de forma estática. Las empresas instalan cortafuegos sin entender qué está bloqueando realmente el filtro, o cómo una simple línea de código mal escrita en su API web puede tirar todo su servidor abajo.

El objetivo de este proyecto es unir todos los cabos sueltos de forma práctica: desde la ejecución manual de un exploit, pasando por la verificación de la vulnerabilidad en el código de backend, el desarrollo del parche lógico de mitigación y la monitorización de la intrusión en un panel de control SOC profesional.

El Doble Modo de Funcionamiento (Seguridad Toggled)

Para demostrar de forma puramente práctica los beneficios inmediatos de implementar código seguro, he desarrollado un interruptor global de seguridad.

Este control altera las rutinas de ejecución del backend de Node.js en tiempo real, permitiendo contrastar de forma directa la diferencia entre un código web mal programado frente a un entorno blindado bajo estándares profesionales de ciberseguridad.

Modo Inseguro / Vulnerable

Autenticación con MD5 débil sin sal, consultas SQL concatenadas y libre inyección de scripts.

Modo Seguro / Protegido

Hasheo btcrypt cost-12, consultas parametrizadas tipadas, limitador de tasa y cortafuegos WAF activo.

● Alternancia en Caliente

El sistema no requiere reiniciar contenedores: la variable de estado del backend se modifica en memoria y adapta los controladores REST al instante.

// Endpoint de alternancia de seguridad
app.post("/api/admin/toggle-security", (req, res) => {
  config.securityMode = req.body.enabled ? "secure" : "vulnerable";
  res.json({ status: config.securityMode });
});

Explotación de Inyección SQL y Parametrización

Código Vulnerable (Inseguro)
// El controlador concatena el texto directamente en la query
const query = `SELECT * FROM "User"
  WHERE email = '${req.body.email}'
  AND password = '${req.body.password}'`;

const resultado = await db.$queryRawUnsafe(query);

Al ingresar admin' OR '1'='1-- en el campo de entrada, la consulta se desvirtúa forzando un bypass de acceso lógico completo al anular la comprobación de la contraseña.

Código Seguro (Mitigado)
// Uso de consultas parametrizadas tipadas con Prisma ORM
const usuario = await db.user.findUnique({
  where: {
    email: req.body.email
  }
});
// La base de datos trata el input estrictamente como un string

Los argumentos de entrada se envían al motor de la base de datos en un canal aislado y puramente como datos de cadena de caracteres (strings), evitando la interpretación lógica de sentencias SQL.

Ataques de Fuerza Bruta y Limitación de Tasa

Ataque por Diccionario Directo

En modo inseguro, un atacante automatiza un diccionario de claves que realiza miles de peticiones al endpoint `/api/login` por segundo.

Al utilizar un algoritmo de hasheo débil e inseguro como **MD5 sin sal**, validar cada contraseña requiere nanosegundos de procesamiento en el servidor, permitiendo descifrar claves débiles en cuestión de minutos.

Implementación de Rate-Limiter y Bcrypt
const loginLimiter = rateLimit({
  windowMs: 15 * 60 * 1000, // 15 minutos
  max: 5, // Límite de intentos fallidos
  message: "Límite superado. Inténtelo más tarde."
});
app.post("/api/login", loginLimiter, handleLogin);

Forzamos el uso de **Bcrypt** con factor de coste 12 (lo que ralentiza el cálculo de hash de forma drástica) y bloqueamos temporalmente la dirección IP mediante el middleware de Express al superar los 5 fallos.

DoS (Denegación de Servicio)

Congelación del Bucle de Eventos

Las aplicaciones web construidas con Node.js son muy veloces porque son monohilo (ejecutan todo en un único hilo de procesamiento).

Sin embargo, esto las hace vulnerables a ataques de saturación. Al recibir miles de peticiones de golpe sin ningún control en modo vulnerable, el bucle de eventos se atasca calculando respuestas y deja de responder a clientes legítimos, tirando la plataforma por completo.

El Cortafuegos Lógico: Middleware WAF de Backend

Protección Lógica Activa

Filtro de Seguridad Proactivo

En vez de depender únicamente de la base de datos, he programado un WAF lógico (cortafuegos de aplicación web) metido directamente en la capa intermedia del backend de Express (`registroPeticiones.ts`).

Este middleware inspecciona de manera recursiva cada parámetro recibido en la API (cuerpo JSON, cabeceras y parámetros de ruta). Aplica filtros de expresiones regulares (regex) para detectar patrones sospechosos de inyección de código SQLi o XSS. Si el modo seguro está encendido, anula la petición con un error HTTP 403 y registra el intento de intrusión en base de datos.

registroPeticiones.ts — Lógica WAF
// Filtros regex para detectar inyección SQL y XSS
const SQL_REGEX = /UNION\s+SELECT|SELECT.*FROM|OR\s+'\d+'\s*=\s*'\d+'/i;
const XSS_REGEX = /<script>|javascript:|onerror|onload/i;

if (SQL_REGEX.test(input) || XSS_REGEX.test(input)) {
  return registrarYBloquearPeticion(req, res);
}

Protección en Navegador

Mitigación de Vulnerabilidades del Lado del Cliente

Además de proteger la base de datos en el backend, es crucial forzar al navegador web del cliente a que aplique políticas estrictas de seguridad.

En modo seguro, la cookie del token JWT se configura con las banderas **HttpOnly** (lo que prohíbe de forma absoluta el acceso a la sesión por parte de scripts, mitigando el impacto de ataques XSS) y **SameSite: Strict** (evitando ataques CSRF). Adicionalmente, las políticas CSP (Content Security Policy) impiden la carga de scripts maliciosos de origen cruzado.

Automatización de Respuesta a Incidentes (n8n)

Automatización sin Código

Flujos Lógicos de Orquestación

Mirar paneles interactivos requiere tiempo de atención que un administrador no siempre tiene. Por ello, he integrado **n8n** en su contenedor propio para automatizar las reacciones defensivas.

Al detectarse un ataque reiterado o catalogado como crítico en el backend, Node.js dispara un Webhook instantáneo hacia el nodo inicial de n8n. El flujo automatizado extrae los metadatos de la agresión (IP de procedencia, tipo de ataque y hora), procesa la información y despacha avisos de alerta a través del servidor de correos SMTP hacia el buzón corporativo.

⚙️ Integración Webhook n8n

// Node.js: Despacha el Webhook ante alertas de alta severidad
async function notificarN8N(payload) {
  await fetch("https://n8n.local/webhook/alert", {
    method: "POST",
    body: JSON.stringify(payload)
  });
}
